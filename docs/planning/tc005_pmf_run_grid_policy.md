# TC-005（修訂草案）— 178A PMF run-level dy 精度政策

**狀態：2026-10-10 使用者明確指定名稱 `pmf_dy_override` 與直接覆寫語意；工作樹已實作、固定候選與完整回歸（102 passed、2 subtests passed）通過，提交隔離待處理。** 本版取代 `reference_alignment_contracts.md` 中 TC-005「在核心硬設 `tap_abs_th=min(...,dy)`、`keep_mass=1`」的舊提案；數值精度由明示設定選擇，不能以追齊 SiCoPR 的 `V_qc` 作為公式驗收。

1. **原因**：目前 178A `run_config` 可選 `pmf_grid_quality`、`pmf_keep_mass`，卻不能直接指定 PMF 電壓步距 `dy`。`dy_rel_As` 與 `dy_abs_max` 固定在 `fixed_config`，使 single/search profile 無法獨立指定精度。Akinwale case 的尾端 PMF 必須同時控制 `dy`、tap 門檻與 `keep_mass` 才能收斂。
2. **依據**：本地 IEEE P802.3dj/D3.0 Annex 178A.1.7.6、Eq. (178A-27)–(178A-29) 定義 ADC clipping／quantization 物理量；`dy` 和 PMF 質量裁切是數值解析政策。現有 178A execution-profile contract 將精度／速度選擇置於 `run_config`。本案 20/10/5/2.5 µV A/B 與 source-fed MMSE 證據在 [`../validation/mmse_input_akinwale_178A.md`](../validation/mmse_input_akinwale_178A.md)。
3. **現況**：`COMRunConfig` 持有 `pmf_grid_quality`、`pmf_keep_mass`；`_resolve_adc_input_pmf_config()` 呼叫 `COMPMFConfig.resolve(As,grid_quality)` 由 fixed-config `dy_rel_As/dy_abs_max` 算出 `dy`。`_resolve_final_com_pmf_config()` 強制 fine grid、keep-mass 1，未接 run-level `dy`。
4. **提案**：178A 各 run profile 新增可選 `pmf_dy_override`（`None` 表示沿用現有 coarse/fine 推導；非空必須是有限正數，單位 V）。pre-DTE ADC PMF、post-FFE ADC-input PMF、final DFE/MLSD PMF 都以目前 run profile 的 `pmf_dy_override` 直接覆寫解析後 `dy`；`pmf_grid_quality` 在 `None` 時仍有效。`tap_rel_As` 仍是 fixed-config policy，`pmf_keep_mass` 仍是 run-config policy。既有 workbook 沒有新 row 時採 `None`，輸出新模板明列此 row。不得改 `P_qc/2`、Gaussian/noise composition 或量化 PSD 公式。
5. **確切函式／檔案**：受保護核心 `src/serdes_coding/models/com_model_178A.py` 的 `COMRunConfig.__post_init__()`、`_resolve_adc_input_pmf_config()`、`_resolve_final_com_pmf_config()`，以及將 `run_cfg` 顯式傳至 final PMF 的 `_run_once()`、`calculate_COM_DFE()`、`calculate_COM_MLSD()`；直接呼叫後兩方法且不傳 profile 時，明定使用 `cfg.execution.single_run` 以保留現有 API。`src/serdes_coding/io/com_excel_io_178A.py` 的 `run_profile()` 讀取新 row；`cases/_templates/178A/config.xlsx` 增加每 profile `pmf_dy_override`；本案 `cases/sicopr_akinwale_vendorx_22db/178A/config.xlsx` 使用 reference-debug profile。文件更新 `docs/models/178A/config_tree.md`、`docs/models/178A/stages/pre_dte.md`、`docs/models/178A/stages/post_ffe.md`、`docs/models/178A/stages/com_dfe.md`、`docs/models/178A/stages/com_mlsd.md`；測試新增 `tests/test_com_model_178A_policy_branches.py`，並調整 `tests/test_com_model_178A_mlsd_eq47.py` 的直接呼叫 fixture。不修改 PMF utility 或 93A。
6. **預期變更量**：顯式 `pmf_dy_override` 可改 pre/post-DTE PMF bin、`V_qc`、`delta`、`S_qn`、`R_n`、FFE/DFE/MSE、final PMF quantiles、COM/MLSD；保持 override 空值時所有輸出逐點與目前一致。
7. **必須不變**：channel、package、pulse、`h_dsamp`、`S_rn/S_xn/S_tn/S_jn`、MMSE solver 方程、ADC `P_qc/2` tail rule、93A、Ad Hoc intrinsic 映射、各 run profile 的獨立性。不得把 SiCoPR 的 `P_qc` tail rule 偷渡為 `dy` 政策。
8. **驗證與驗收**：Akinwale locked candidate、67 GHz branch，`tap_abs_th≤dy`、`pmf_keep_mass=1` 時，`pmf_dy_override=20/10/5/2.5 µV` 的 `V_qc` 應為 `41.940/41.940/41.945/41.945 mV`（各容許一個對應 bin）；`S_qn` 依 Eq. (178A-26)/(27) 隨 `V_qc` 一致變動，其他四項 PSD 不變。新 row 空值須重現既有 golden；單跑及 search 各 profile 分別核對解析 dy；跑相關單測與固定 golden 後，再看搜索。SiCoPR `41.62 mV` 不作 dy 驗收值，因收斂 dy 仍差約 `0.325 mV`。
9. **影響**：93A 不變；178A single-run、search-sweep、search-final 可分別設 dy。預設 `None` 的既有行為不變；顯式覆寫會影響對應 profile 的 MMSE／final COM 數值與耗時。GUI 使用既有 run-policy row 顯示，不另改 UI 控制流程。
10. **回退邊界**：核准後，受保護模型變化及直接測試以專用提交隔離；parser／template／case／文件分開提交。記錄提交 SHA 與 parent；回退該兩提交，不使用整檔 reset，以保護工作樹原有未提交修改。

**本案 debug 設定**：`single_run.pmf_dy_override=1e-5 V`、`single_run.pmf_keep_mass=1.0`；case 的 `tap_rel_As≈3.1579e-5` 使 `tap_abs_th≈1e-5 V`。這使本地 PMF 數值收斂，**不會**使其 `V_qc` 自動等於 SiCoPR；若要比對方法分支，需另行明示 tail/noise 定義。
